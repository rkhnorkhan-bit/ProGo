# F31g — ручная копия без блокировки интерфейса

Этап подготовлен от `49bea12`. F31 остаётся **OPEN**: локальные проверки исходников
не заменяют Windows runtime CI и замеры на Windows Rescue/HDD/VHDX.

## Что изменилось

Команда «Создать копию сейчас» запускает один worker настоящего `BackupService`.
Окно показывает состояние, отмену и итог; интерфейс, настройки и команды остановки
подключений остаются доступны. Повторное создание, восстановление, очистка копий
и установка обновления недоступны до окончания worker. Повторный вызов создания
получает ту же задачу. Общая блокировка writers также исключает одновременное
создание двух C# копий и конфликты имён/retention.

Отмена проверяется перед каждым файлом, между блоками копирования и вычисления
SHA-256. Незавершённая новая папка удаляется в worker; текущие файлы и предыдущие
копии не удаляются. Ссылки в новой папке запрещают её рекурсивное удаление.
До принятия полной проверенной копии отмена не запускает retention старых копий;
после этой границы уже начатый retention завершается. PIN, шифрование и формат
хранилища, состав восстановления и v1 SHA-256 индекс остаются прежними.

Результат применяется через постоянный UI dispatcher владельца. `Dispose`
отменяет операцию и закрывает окно, не ожидая зависший дисковый вызов; worker
заканчивает уборку без поздних обращений к закрытому UI. Нормальный выход и
обслуживание отменяют копирование и ждут его фактического завершения до 3 секунд.
Если накопитель ещё удерживает операцию, выход отклоняется, ProGo остаётся открытой
и снова разрешает настройки/остановку подключений. Worker сохраняет single-flight
до реального окончания, чтобы безопасный отказ не породил второй копировщик.
Системный дисковый вызов невозможно принудительно прервать `CancellationToken`;
программа не объявляет его завершённым раньше фактического окончания.

Сведения о копии читают `manifest.txt` одним snapshot вместо девяти отдельных
`ReadAllLines`. Девять полей UI, регистр ключей, первый дубликат, пустое первое
значение и fallback старых копий сохранены. Следующее открытие получает свежие
сведения; долговременного metadata cache нет.

## Оставшиеся интеграции

`Program.cs` всё ещё синхронно вызывает `EnsureVersionBackupExists("startup")`
до создания tray context и message pump. Комментарий о быстром tray startup
не отражает этот вызов; стартовая базовая копия должна получить отдельный
согласованный lifecycle worker (следующий F31h).

`StartRestore` читает список и metadata копий синхронно перед chooser. Этот этап
уменьшает metadata reads, но не переносит весь listing в worker. Предпросмотр
retention и подтверждённая очистка в `CleanupBackups` тоже остаются синхронными.
Подготовка выбранной restore copy уже выполняется отдельно в `Task.Run`; это
не делает остальные действия раздела асинхронными. Эти пробелы и реальное HDD
профилирование не закрываются этим этапом.
