## Проблема и цель

Исходный файл сообщает об историческом отказе доступа к зашифрованному ключу
из-за ACL, последующем успешном интерактивном SSH после исправления прав,
остановленном агенте с ручным запуском и расхождении выбранного прямого target
с рабочим SSH-алиасом. Эти сведения **не перепроверялись на ПК или VPS** при
включении документа. Утверждение файла о прежних скрытых ошибках и повторах
не подменяет аудит текущего кода: часть обработки уже реализована отдельно.
Запуск агента сам по себе не доказывает исправление аутентификации.

ProGo должен проверять Windows `ssh-agent`, при допустимых условиях инициировать
его запуск, безопасно использовать зашифрованный ключ и подключать SSH/SOCKS
через выбранный профиль без ручных PowerShell-команд в обычном сценарии.
Требования одинаковы для разных ПК, Windows-пользователей, ключей, алиасов и
VPS; конкретные адреса, пользователи и пути не являются значениями по умолчанию.

## Обязательные функциональные требования

### Установка и общесистемная служба

1. Установщик проверяет наличие `OpenSSH Authentication Agent` (`ssh-agent`).
2. Изменение startup policy — отдельная **неотмеченная по умолчанию** опция.
   Только после явного согласия конечного пользователя установщик может
   запросить необходимые повышенные права, установить `Automatic` и запустить
   службу. Этот документ не выполняет таких действий на чьём-либо ПК.
3. Без согласия установщик сохраняет системную конфигурацию. Приложение может
   использовать уже доступный агент; изменение политики не становится условием
   установки ProGo или подключения другими рабочими методами SSH.
4. Отсутствующая служба, запрет политики организации и ошибка запуска дают
   понятную причину и допустимые дальнейшие действия, а не падение приложения.
5. Uninstall не удаляет службу и не сбрасывает её настройки: агент общий для
   других приложений. Обновление сохраняет профили, ключи и чужие настройки.

### Каждый запуск ProGo

1. Состояние службы определяется в фоне без ожидания диска или SCM на UI.
2. Остановленную службу разрешено попытаться запустить только с имеющимися
   правами. UAC при каждом старте приложения не появляется.
3. `Access denied`, `Disabled`, `Service not found` и другие ошибки различаются;
   журнал и UI показывают конкретную безопасную причину и следующее действие.
4. Доступность агента (`ssh-add -l` или безопасный эквивалент) и наличие нужного
   выбранному профилю ключа проверяются отдельно. Количество ключей не доказывает
   наличие подходящего или успешную аутентификацию на сервере.
5. Повторные проверки, запуск службы и `ssh-add` координируются: конкурирующие
   потоки не создают одновременные операции и не подвешивают интерфейс.

### SSH-профиль и ключ

1. Используются target и `IdentityFile` реально выбранного профиля, включая
   пользовательский SSH config, алиасы и effective параметры OpenSSH.
2. Если нужный ключ уже доступен агенту, приложение переходит к проверке
   подключения без повторного запроса парольной фразы.
3. Если ключ отсутствует в агенте, пользователь получает действие добавления
   через `ssh-add` и один ввод парольной фразы в проверенном безопасном
   интерактивном сценарии. Скрытый `Process.Start` не считается таким сценарием.
4. Парольная фраза не сохраняется в settings, логах, аргументах процессов,
   переменных окружения, телеметрии или иных диагностических материалах.
5. Незашифрованный ключ и другие рабочие методы SSH-аутентификации работают без
   искусственного обязательного требования `ssh-agent`. Учитываются настройки
   `IdentityAgent` и `IdentitiesOnly` выбранного профиля.
6. Небезопасные ACL приватного ключа дают отдельную диагностику `bad permissions`
   и предложение точечного исправления только после подтверждения. Автоматической
   правки ACL ключа или других пользователей нет.

### SSH/SOCKS и восстановление

1. После проверки готовности выбранного метода аутентификации фоновый SSH
   использует `BatchMode=yes`; скрытый процесс не ожидает парольную фразу.
2. Алиас не заменяется прямым `user@host`, если это меняет ключ, порт или другие
   параметры SSH config. Диагностика и реальный запуск используют общий профиль.
3. Отслеживаются stderr, код завершения и настоящий SOCKS-протокол. Занятый TCP-порт
   не считается доказательством готовности или владения.
4. Постоянные отказы — ACL, исчерпанные подходящие ключи/`Permission denied`,
   неправильный профиль и параметры — отделяются от временных сетевых ошибок.
5. Бесполезные повторы при постоянной ошибке приостанавливаются до изменения
   условий с видимой причиной. Временные ошибки используют ограниченный backoff,
   отмену и корректное завершение. Число повторов этим документом не задаётся.
6. Нет дублирующихся `ssh.exe`, завершения чужих процессов или захвата чужого
   SOCKS-порта. Отказ одного кандидата не отменяет разрешённый профильный fallback.
7. Windows/CLI proxy включаются после успешной проверки локального SOCKS.
   При остановке восстанавливаются только настройки, которыми управлял ProGo.

### UI и доступность

Отдельно показываются состояния:

| Объект | Требуемые состояния |
| --- | --- |
| SSH-agent | Работает, остановлен, недоступен, ошибка прав. Startup policy не смешивается с текущим состоянием службы. |
| SSH-ключ | Готов, требуется разблокировка, небезопасные ACL, не найден. |
| SSH-профиль | Активный алиас или адрес без секретов. |
| SSH | Подключается, аутентифицирован, ошибка с причиной. |
| SOCKS | Запущен, остановлен, порт занят, ошибка. |

Предусматриваются действия **«Запустить агент»**, **«Добавить ключ»**,
**«Проверить SSH-профиль»**, **«Повторить соединение»**. Недоступное действие имеет
объяснение. Pending, отмена, ошибка и повтор не теряют выбранный профиль и не
публикуют устаревший результат. Новые элементы входят в F16/F17/F29.

## Технические ограничения

- Использовать Windows Service API/.NET, без обязательного запуска PowerShell
  при каждом старте. Системный OpenSSH и его `ssh-add` должны согласовываться.
- Service/key/SSH операции выполняются асинхронно относительно UI с таймаутами,
  отменой и учётом полного времени жизни принадлежащей операции. Таймаут ожидания
  read-only native query не выдаётся за принудительную отмену уже идущего OS вызова.
- До реализации разблокировки выбрать и проверить рабочий Windows-механизм:
  управляемый интерактивный процесс или корректно реализованный `SSH_ASKPASS`.
  Выбранный механизм обязан соблюдать запрет передачи/сохранения секретов выше.
- Сохранять подробную структурированную причину и безопасный журнал без секретов;
  исходный stderr не выводить в общие отчёты без соответствующей очистки.
- Существующие настройки и профили мигрируют без потерь. Наличие файла ключа,
  работающей службы или успешного `ssh -G` не объявляется аутентификацией.

микрозадача. Прежние принятые F31-R01–R04 сохраняют собственные границы приёмки.

ворота. Каждый небольшой шаг подтверждается отдельно; успешной сборки недостаточно.

## Критерии приёмки

| № | Сценарий | Ожидаемый результат |
| --- | --- | --- |
| 1 | Агент работает, нужный ключ загружен. | Подключение без запроса парольной фразы. |
| 2 | Агент остановлен, есть права на запуск. | Запуск агента и продолжение подключения. |
| 3 | Агент остановлен, прав нет. | Понятная причина и действие; отзывчивый UI. |
| 4 | Зашифрованный ключ не загружен. | Однократная интерактивная разблокировка без сохранения/утечки секрета. |
| 5 | Target выбран как SSH-алиас. | Используются его effective Host-параметры, включая IdentityFile. |
| 6 | Прямой target не имеет подходящего ключа. | Понятная ошибка профиля/ключа без бесконечного бесполезного цикла. |
| 7 | Небезопасные ACL ключа. | `bad permissions`, без самовольного изменения ACL. |
| 8 | Агент недоступен, незашифрованный ключ работает напрямую. | SSH/SOCKS может подключиться без агента. |
| 9 | Временный сетевой сбой. | Ограниченный backoff и восстановление с работающей отменой. |
| 10 | Приложение закрывается. | Нет оставленных принадлежащих ему туннелей и завершённых чужих процессов. |
| 11 | Установка, обновление, удаление. | Сохранены профили, приватные ключи и чужие системные настройки. |

**Release gate:** все критические сценарии PASS, причины SSH различимы
пользователем, SOCKS и Windows/CLI proxy проверены end-to-end. Для каждого FAIL,
SKIP и NOT_CHECKED фиксируются причина и граница. Новый документ этого gate не
закрывает и не объявляет текущий пакет готовым.

## Что не входит в разрешённые изменения

- Изменения `authorized_keys`, `sshd` и системы VPS без отдельного согласования.
- Удаление парольной фразы приватного ключа ради автоматизации.
- Изменение ACL других SSH-ключей и Windows-пользователей.
- Жёстко заданные личные адреса, пользователи, alias и пути для всех установок.
- Установка и проверки на ПК, VPS или телефоне владельца до цельного пакета.

Зоны интеграции: `ProxyService`, `SshProfileDiagnostics`, `SshConnection` и
`OpenSshClient` в `Core`, `SshInteractiveLogin`, UI/context startup, installer,
uninstall и соответствующие tests. Точная граница каждого шага фиксируется в его
доказательствах. Текущий инвентарь и счёт: [REMAINING_SUBTASKS_8.md](REMAINING_SUBTASKS_8.md).
