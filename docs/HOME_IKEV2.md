# iPhone через домашний ПК

Экспериментальный режим: встроенный IKEv2 на iPhone обращается к домашнему
роутеру, ProGo на Windows передаёт зашифрованные IKE/ESP-пакеты через свой
локальный SSH/SOCKS-туннель, а strongSwan на VPS проверяет пользователя и
выпускает трафик в интернет. Виртуальная машина и приложение на iPhone не нужны.

Это **пересылка VPN до VPS**, а не IKEv2-сервер на Windows. ProGo не получает
пароль iPhone и не расшифровывает VPN-трафик. До успешной аутентификации VPS
обрабатывает только установление VPN; обычный доступ в интернет не предоставляется.

Состояние разработки: автоматические тесты проверяют транспорт C# → SOCKS → Python →
UDP, разделение клиентов и ограничения ресурсов. Они не подтверждают совместимость
с конкретным iPhone, домашним роутером, strongSwan или мобильным оператором.
Перед постоянным использованием нужно пройти проверку ниже.

## Условия

- Windows 10/11 с ProGo, рабочим OpenSSH SOCKS-туннелем на нужный VPS и .NET Framework 4.8.
- Домашний публичный IPv4 или DNS-имя, указывающее на него. При CGNAT входящий
  проброс без дополнительных средств недоступен. IPv6-вход пока не реализован.
- Доступ к настройкам домашнего роутера. ПК включён и не переходит в сон.
- Уже настроенный strongSwan IKEv2 на VPS: серверный сертификат, пользователи,
  адресный пул, `encap = yes`, маршрутизация/NAT и DNS. Этот модуль не заменяет
  настройку VPN-сервера. Нужен его исходный `.mobileconfig`.
- Мобильная сеть должна пропускать IKEv2 к **домашнему адресу**. Пересылка через
  ПК не устраняет блокировку протокола на первом участке.

## 1. Приёмник на VPS

Используйте серверные файлы из той же версии, что и Windows-клиент. После обновления
они находятся на ПК в `%LOCALAPPDATA%\ProGo\scripts\home-vpn\server`.
Перенесите каталог `server` на VPS через SCP/SFTP. В каталоге, содержащем `server`,
выполните команду с правами администратора:

```bash
sudo bash server/install-ikev2-relay.sh VPS_IPV4
```

Вместо `VPS_IPV4` укажите локально назначенный IPv4, который используется
в `local_addrs` strongSwan. Установщик проверяет адрес и активность strongSwan,
ставит `/opt/progo-ikev2-relay/ikev2_relay.py` и службу
`progo-ikev2-relay.service`. Приёмник слушает **только 127.0.0.1:17878/TCP**;
доступ с ПК идёт через SSH. Не открывайте этот порт наружу.

Установщик не меняет правила firewall, SSH, сертификаты, пользователей VPN,
существующий NAT или IP forwarding. На VPS нужна Python 3.8+; дополнительных
Python-пакетов нет. После установки локальная проверка подтверждает доступность
приёмника, а не успешность VPN-аутентификации.

Если в SSH используются `PermitOpen`/`AllowTcpForwarding`, выбранной SSH-учётной
записи нужен доступ к `127.0.0.1:17878`. SSH/SOCKS должен вести на **тот же VPS**.
Внешний SOCKS-прокси с запретом доступа к loopback для этого режима не подходит.

## 2. Windows и роутер

Обновите ProGo через пункт **«Обновить ProGo»** в меню значка в трее.
Режим доступен начиная с версии **0.1.28**. Исходники собирать не требуется.
Обновление устанавливает приложение и вспомогательные файлы; настройку VPS,
роутера и профиля телефона выполняют отдельно по этой инструкции.

В PowerShell **от администратора**, под той же учётной записью Windows,
разрешите входные UDP-порты установленного ProGo:

```powershell
$ProGoDir = Join-Path $env:LOCALAPPDATA 'ProGo'
& "$ProGoDir\scripts\Enable-HomeVpnFirewall.ps1" -ProGoExe "$ProGoDir\ProGo.exe"
```

Закрепите LAN-адрес ПК в DHCP роутера. Настройте два правила:

| Внешний порт роутера | Протокол | Назначение в домашней сети |
| --- | --- | --- |
| 500 | UDP | LAN-адрес ПК, порт 15000 |
| 4500 | UDP | LAN-адрес ПК, порт 14500 |

Не выбирайте TCP. Если роутер сам использует IKEv2 на этих портах, потребуется
разрешить конфликт на роутере. ProGo использует другие локальные порты, поэтому
не нужно отключать Windows IKEEXT. Не выставляйте наружу порты SOCKS или HTTP-прокси.

В меню ProGo запустите SOCKS, затем **«VPN для iPhone…» → «Запустить»**.
Режим выключен по умолчанию; после перезапуска ProGo его нужно включить снова.
После смены SSH-профиля или порта SOCKS перезапустите этот режим.
Кнопка «Остановить SOCKS» также останавливает пересылку VPN.

## 3. Профиль iPhone

На VPS создайте отдельный профиль из исходного. В примере ниже `vpn-original.mobileconfig`
— исходный файл, а `home.example.org` — условное имя. Замените его своим публичным
домашним DNS-именем или IPv4; этот пример не является готовым адресом подключения.

```bash
python3 server/make_home_profile.py ./vpn-original.mobileconfig \
  --server home.example.org \
  --output ./vpn-home.mobileconfig
```

Утилита меняет адрес подключения на домашний и отключает MOBIKE для этого профиля,
сохраняет идентификатор/сертификат VPS, параметры аутентификации, маршруты и DNS.
Исходный файл не перезаписывается. Перенесите новый `.mobileconfig` на iPhone и
установите его через системные настройки. Не публикуйте профиль: исходный файл
может содержать учётные данные. Если исходный профиль был подписан, сначала нужен
его неподписанный plist-оригинал, а не CMS-контейнер.

Адрес подключения и удалённый идентификатор теперь различаются:

| Поле | Значение |
| --- | --- |
| Сервер / RemoteAddress | Домашний публичный адрес |
| RemoteIdentifier | Прежний идентификатор VPN-сервера на VPS |
| Логин и пароль | Существующая учётная запись strongSwan |

Первая проверка — через мобильный интернет, чтобы не зависеть от NAT loopback
домашнего роутера. Выберите новый профиль и включите VPN. При переходе между
Wi-Fi и мобильной сетью может понадобиться переподключение: MOBIKE отключён,
чтобы серверные дополнительные адреса не позволили обойти домашний узел.

## Проверка и диагностика

1. В ProGo растёт «с телефона»: UDP дошёл до Windows. Ноль при попытке подключения
   означает, что нужно проверить домашний адрес, проброс, firewall или мобильную сеть.
2. Растёт «на VPS»: пакет записан в транспорт. Это ещё не подтверждение VPN-входа.
3. На VPS выполните `swanctl --list-sas` и
   `journalctl -u strongswan.service --since '5 minutes ago' --no-pager`.
   Для полного успеха нужны установленная IKE SA и CHILD SA.
4. С VPN на iPhone проверьте внешний IPv4 в браузере: он должен быть адресом VPS.
   Проверьте сайты, Telegram, DNS, поведение IPv6 и звонок отдельно.
5. Остановите пересылку: VPN-трафик через этот маршрут должен прекратиться.
   Поведение телефона при отключённом VPN зависит от настроек iOS-профиля.

Приёмник отправляет IKE/ESP в strongSwan с loopback-адреса самого VPS. Поэтому
в журнале strongSwan внешнего IP телефона не будет. Для диагностики локального
участка можно захватывать UDP 500/4500 на интерфейсе `lo` VPS. Если strongSwan
ограничивает адреса клиентов, учитывайте этот loopback-источник; не отключайте
проверку сертификатов или пароля для устранения проблем.

Если «обратно» растёт, но iPhone не подключается, проверяйте IKE-аутентификацию и
сертификаты по журналу. Счётчик пакетов в ProGo не означает успешную авторизацию.

## Ограничения и откат

- UDP переносится внутри TCP/SSH. Потери на участке ПК–VPS могут заметно увеличить
  задержку звонков и всех потоков. Это компромисс ради использования существующего
  туннеля; производительность нужно измерить на реальной линии.
- Открытые UDP-порты принимают запросы до авторизации, как обычный VPN-сервер.
  Авторизацию выполняет VPS. В ProGo ограничены число потоков, скорость создания
  потоков, очереди и время простоя. Эти пределы не заменяют защиту от DDoS.
- Ограничение VPS по loopback означает, что любой уже допущенный к SSH forwarding
  пользователь этой машины может обратиться к приёмнику. Для выхода в интернет
  всё равно нужны действительные учётные данные IKEv2.
- Нет прямого выхода с ПК при отказе SOCKS. IPv6 внутри VPN переносится как часть
  зашифрованных пакетов; правила маршрутизации и защиты от утечек остаются
  ответственностью исходного профиля и strongSwan.
- Остановите режим в ProGo, удалите два правила проброса на роутере. В PowerShell
  от администратора удалите правила ProGo:

  ```powershell
  $ProGoDir = Join-Path $env:LOCALAPPDATA 'ProGo'
  & "$ProGoDir\scripts\Enable-HomeVpnFirewall.ps1" -ProGoExe "$ProGoDir\ProGo.exe" -Remove
  ```
- На VPS: `systemctl disable --now progo-ikev2-relay.service`. Это не останавливает
  существующий strongSwan и не меняет его пользователей/сертификаты.

## Для разработчиков

`tests/test_ikev2_relay.py` проверяет настоящий обмен сокетами с UDP-эхо вместо
strongSwan. `tests/RelayHarness.cs` собирается с тем же исходником транспорта, что
и ProGo. В Windows CI используется .NET Framework; локально возможен .NET 8:

```bash
dotnet build tests/RelayHarness.csproj -c Release
PROGO_RELAY_TEST_COMMAND='["dotnet","tests/bin/Release/net8.0/RelayHarness.dll"]' \
  python3 -m unittest discover -s tests -p 'test_*.py' -v
```

Формат канала описан в `server/ikev2_relay.py`. Клиент выбирает только IKE/500 или
NAT-T/4500. Адрес назначения жёстко задаётся при установке приёмника. Криптография
IPsec, EAP и выдача адресов остаются в strongSwan. Пакеты и пароли не журналируются.
