# Измерение установленного ProGo в Windows Rescue

Этот helper запускает владелец на своём Windows 11 / .NET Framework 4.8 / Windows
PowerShell 5.1. Он читает состояние выбранного процесса и Windows. Запуск ProGo,
SSH/VPS, сетевые подключения, запросы ключей, изменения служб, прокси, файлов
настроек и журналов не выполняются. Отчёт не содержит командные строки процессов,
заголовки окон, содержимое журналов/настроек, ключи, passphrase или токены.

Выберите фактический PID. Если ProGo не запущен, можно проверить только выбранный
EXE; отчёт явно скажет, что работа приложения не подтверждена.

```powershell
Get-Process ProGo | Select-Object Id, Path
```

Подставьте выбранный `Id` вместо примера `1234`. Путь к helper относится к
распакованному кандидату; его можно использовать для измерения ранее установленной
версии, не устанавливая кандидата. Helper не запускается автоматически.

```powershell
.\scripts\Measure-RescueProGo.ps1 -ProcessId 1234 -DurationSeconds 30
```

Версия и build identity берутся из ресурсов фактического EXE этого PID, а не из
`VERSION` репозитория или лежащей рядом копии. Если дополнительно указан
`-ExecutablePath`, несовпадение с выбранным PID отмечается как FAIL. Версия старого
EXE может не содержать commit: отчёт не восстанавливает его предположением.

Порты по умолчанию **не заданы**, их результат — NOT_CHECKED. Передайте фактические
SOCKS и HTTP bridge порты из текущего окна диагностики/настроек ProGo. Например,
следующая команда подходит **только если показаны именно 1080 и 1881**; автоматически
выбранный HTTP bridge порт может быть другим.

```powershell
.\scripts\Measure-RescueProGo.ps1 -ProcessId 1234 -DurationSeconds 30 -SocksPort 1080 -HttpPort 1881
```

Вывод идёт только в stdout. Для отдельного файла владелец явно выбирает путь:

```powershell
.\scripts\Measure-RescueProGo.ps1 -ProcessId 1234 -ReportPath .\rescue-measurement.txt
```

Этот выбранный файл записывается/заменяется; каталоги автоматически не создаются.
Префикс текущего профиля в пути EXE маскируется как `%USERPROFILE%`. Перед передачей
отчёта проверьте остальные пути: отчёт показывает расположение выбранного EXE и
найденного `ssh.exe`, а не пытается угадывать назначение каждого имени каталога.

Измерение длится 2–300 секунд, интервал образцов — 250–5000 мс. Начальная загрузка
PowerShell и компиляция локального helper через Add-Type не входят в этот интервал.
Внутри измерения общая продолжительность ограничена; отдельный probe ждётся не
дольше 5 секунд или оставшегося времени. Заблокированный probe завершает сеанс,
следующий worker не запускается. Завершение выбранного процесса останавливает
сбор; его PID не переоткрывается для случайно появившегося нового процесса.

## Что проверяет отчёт

| Данные | Источник и предел доказательства |
| --- | --- |
| EXE, версия, build identity | QueryFullProcessImageName и ресурс версии выбранного файла. Не доказывает равенство загруженных байтов файлу, если другой процесс заменил EXE после запуска. |
| CPU | Разница GetProcessTimes между образцами, нормированная по числу логических процессоров. Не включает CPU дочернего ssh.exe. |
| RAM | Максимум working set и private bytes среди образцов GetProcessMemoryInfo. |
| I/O | Разница GetProcessIoCounters; включает кэш и операции устройств. Это не счётчик физического диска/HDD/VHDX и не атрибуция всех задержек накопителя. |
| Windows Responding | Видимые окна выбранного PID и IsHungAppWindow. Отсутствие признака зависания не измеряет скорость кликов/перерисовки; без видимого окна — NOT_CHECKED. |
| Дочерние SSH | Toolhelp snapshot и цепочки parent PID, только имя ssh.exe. Наличие процесса не определяет фазу подключения/ожидания passphrase. |
| OpenSSH | Предпочтение Windows Sysnative/System32 OpenSSH, затем абсолютные каталоги PATH; относительные записи PATH игнорируются. Путь и ресурсная версия файла, без запуска ssh.exe. |
| ssh-agent | SCM с правами query status/config: Running, Stopped, переходное/недоступное состояние и отдельный режим Disabled/Manual/Automatic. Наличие загруженного ключа не проверяется. |
| SOCKS/HTTP порт | Единственный read-only снимок локальных TCP listeners для переданных фактических IPv4 портов. Не доказывает принадлежность ProGo, SOCKS5 протокол, внешний маршрут или успешную аутентификацию. |

PASS означает получение указанного наблюдения, а не приёмку всей программы.
FAIL означает отсутствующий выбранный процесс/файл/listener, остановленный агент,
несовпадение PID/EXE или найденный Windows признак зависания. Неизвестные/непереданные
данные и проверки, которых helper не делает, остаются NOT_CHECKED. Отчёт не назначает
универсального «допустимого CPU/диска» и не объявляет HDD/VHDX тест пройденным.

Для сопоставимого владельческого измерения запустите helper сначала в покое, затем
повторите с обычными действиями в интерфейсе и попыткой подключения. Сам helper
не выполняет эти действия. Сопоставьте отчёты с реальными задержками UI и графиками
диска в Диспетчере задач/Мониторе ресурсов. Недоступный VPS/незапущенный агент не
должны менять возможность взаимодействовать с ProGo; это нужно наблюдать на
реальном Rescue-компьютере, а не выводить из CI.

## Регрессии и приёмка

`RescueMeasurementTests.cs` проверяет расчёт по известным счётчикам, маскирование и
allowlist текста, отмену/тайм-аут с одним worker, сбой probe, реальные метрики текущего
процесса, неизменность SCM и listener без подключения, реальный выход дочернего
процесса и подсчёт SSH-named fixture без чтения аргументов. PowerShell тест вызывает
реальный упакованный helper, проверяет stdout, отсутствие автоматического отчёта,
неизменность соседних настроек, явный ReportPath и PID/EXE mismatch.

Эти тесты входят в `Test-ProGo.ps1` и требуют Windows. Реальные показатели конкретной
установленной версии ProGo и HDD/VHDX до запуска владельцем: **NOT_CHECKED**.

Определения Win32: [GetProcessMemoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessmemoryinfo)
и [IsHungAppWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-ishungappwindow).
