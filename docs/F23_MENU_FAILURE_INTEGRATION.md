and Menu second, preserving the original failure, Stop/finally/cleanup, no Install OK or Launch and
no full auxiliary/runtime rollback until remaining Legacy/full outcome requirements pass. Fresh Menu
mutation needs verified Startup settlement, exact current snapshot/runtime/identity/receipt/trusted
locations and native ownership. Existing Menu intent alone never authorizes a repeated native call.

classifies original-observed and reads/persists the existing scoped result; not-applied, partial or
corrupt admission blocks. Without admission, only startup-observed AND independently valid durable
Startup result allow the existing owned Menu API. Its durable admission must flush/readback/revalidate
before native deletion. Missing result after accepted deletion may be created from freshly verified
read-only proof. Existing valid result is reused by observation; corrupt/partial/foreign result is
not rewritten. Failure returns blocked and never replaces the original installation exception.

therefore uses the already-tested Menu context, which independently verifies physical Startup original
state plus canonical Startup admission/result, Menu admission, exact receipt, runtime/snapshot and
Legacy linkage. This permits honest scoped observation even if the older Startup adapter returned
blocked due to missing primary. It grants no automatic mutation, full rollback or retry permission.
