# F22p: защищённый перенос домашнего VPN

F22 из аудита, с. 15, остаётся **OPEN** до проверки итоговой интеграции на
Windows. Этап добавляет отдельный переносимый архив домашнего VPN, не меняя
обычные резервные копии и откат, PIN или шифрование vault. Локальная среда —
Linux без компилятора Windows/.NET Framework: сборка и native tests здесь
**NOT_CHECKED**. Перенос между пользователями Windows и между ПК также
**NOT_CHECKED**; независимый decoder и дочерний процесс под тем же пользователем
не заменяют эту проверку.

## Обычная копия, перенос и другой VPS

Обычная резервная копия хранит исходные DPAPI-байты VPN как архив. Она не
переносит ключи защиты Windows и не гарантирует чтение после переустановки или
под другим пользователем. Откат программы сохраняет текущие личные файлы.

Отдельный `.progo-vpn` экспорт расшифровывает выбранный каталог
`home-vpn-private` текущим пользователем Windows и шифрует содержимое отдельной
парольной фразой. Импорт сначала проверяет пароль, подлинность и состав в памяти.
Второе явное действие «Импортировать этот состав» записывает новую защиту DPAPI
текущего пользователя в новый чистый каталог. Существующий каталог, включая
пустой, не заменяется и не удаляется. После успешного импорта нужно перезапустить
ProGo для загрузки данных; импорт сам не запускает SSH, relay или прокси.

Перенос сохраняет исходный VPS и доверенные данные доступа. Для другого VPS
нужен новый доступ через существующий мастер; архив не переписывает server ID,
CA, SSH host key или привязки незавершённых запросов. Экспорт создаёт копию
доступа и не отзывает исходный. Проверка формата не подтверждает доступность
сервера или отсутствие отзыва доступа.

## Состав и сохранение незавершённых запросов

| Файл при наличии | Обработка |
| --- | --- |
| `access.dat` | VPN-токен с ограниченным клиентским ключом, CA и host key; строгий известный набор полей и существующая проверка токена. |
| `owner.dat` | Адрес, порт и SSH-пользователь владельца; `KeyFile` очищается только в переносимом представлении. Локальный ключ владельца выбирают на новом ПК отдельно. Исходный файл не меняется. |
| `home-address.dat` | Проверенный внешний адрес/DDNS дома. |
| `share-<32 lowercase hex>.dat` | Канонический HTTPS-origin сервиса профилей. |
| `setup-request.dat` | Точный известный JSON из 7 полей, включая прежний ID, исходный VPS и сохранённый результат, если он получен. |
| `admin-request.dat` | Точный JSON из 10 полей выдачи приглашения: прежний ID, frozen VPS, source invite и server ID, результат при наличии. |
| `share-request.dat` | Точный JSON из 8 полей установки HTTPS-сервиса: прежний ID, действие `share`, frozen VPS/пользователь/порт/домен/server ID. Без token/result/TTL. |

Известные запросы переносятся без изменения исходных байтов JSON. Предпросмотр
показывает их имена, исходные endpoint и HTTPS-домен без ключей или токенов.
Импорт не потребляет запрос и не снимает блокировки повторной выдачи. Неизвестный
постоянный файл, новый неподдерживаемый request или промежуточный `.new` блокирует
экспорт вместо молчаливой потери запроса. Дубли JSON-полей и записей, неизвестные
поля, неверные типы и пути отклоняются.

Временные `session-*`/`admin-*` каталоги исключены без обхода содержимого. `.ssh`,
приватный административный SSH-ключ, OpenSSH-agent, настройки/vault, журналы,
снимки владения Windows/CLI proxy и содержимое рабочего стола не входят. Ссылки
и junction в источнике, файле архива и предках целевого пути отклоняются.

## Контракт формата v1

Пароль содержит минимум **16 Unicode scalar values**, не 16 UTF-16 code units;
например, восемь emoji не проходят минимум. Максимум — **1024 байта строгого
UTF-8**. Ввод не нормализуется и не обрезается. Пароль независим от vault PIN и
passphrase SSH, не записывается в настройки, argv, файлы или журналы.

| Канонический заголовок | Значение |
| --- | --- |
| Magic, 17 байт | ASCII `PROGO-VPN-EXPORT` и завершающий NUL |
| Version, Int32 LE | `1` |
| Iterations, Int32 LE | Только `600000` |
| Ciphertext length, Int32 LE | Положительный кратный 16 размер, максимум 4 MiB + 16 |
| Salt | Случайные 32 байта |
| IV | Случайные 16 байт |

PBKDF2-HMAC-SHA256 производит 64 байта: первые 32 для AES-256-CBC/PKCS7,
последние 32 для HMAC-SHA256. Полный 32-байтовый MAC покрывает **весь
канонический заголовок и ciphertext**. Полный MAC сравнивается циклом без
раннего выхода до создания decryptor и разбора plaintext. Неизвестная версия,
KDF, неверные длины и trailing bytes отклоняются; untrusted iterations не
могут увеличить работу KDF.

Plaintext payload: Int32 LE version `1`, Int32 LE count, затем упорядоченные
по ordinal имени записи `name byte length`, UTF-8 name, `value byte length`,
исходные UTF-8 данные. Максимум: 128 записей, 80 байт имени, 128 KiB на значение,
4 MiB всего. Имена ограничены указанным allowlist; пути, дубли и trailing bytes
отклоняются. После расшифровки применяется строгая проверка известных схем.

Plaintext временных файлов нет: экспорт создаёт только ciphertext во временном
соседнем файле, flush и atomic move публикуют новый файл без перезаписи.
Импорт создаёт соседний закрытый ACL-каталог, заново защищает и проверяет каждую
DPAPI-запись, затем одним same-volume `Directory.Move` публикует целый каталог.
Отмена до этой границы удаляет только собственный staging; отмена после
публикации не откатывает принятый результат. Байтовые буферы пароля, ключей и
plaintext очищаются в `finally`; управляемые строки и внутренние копии Windows
DPAPI/.NET не позволяют обещать полное стирание всей памяти процесса.

## Операции и проверки

Файловая работа, DPAPI и KDF выполняются в worker. На каждое действие формы
установлен общий срок **60 секунд**, после которого CTS запрашивает отмену.
Это не принудительное завершение заблокированного системного вызова: его actual
worker остаётся во владении формы/context до возврата. Следующая проверка
отмены запрещает публикацию, а результат сообщает по-русски об истечении срока.
После уже принятого atomic move timeout не откатывает результат. Чтение/запись
ограничены размерами, проверяют отмену; KDF — один фиксированный вызов без
интерактивного ввода и автоматических повторов. Собственный semaphore запрещает конкурирующие
операции переноса. Источник проверяется дважды по именам и SHA-256 зашифрованных
файлов, поэтому изменившийся во время снимка источник не публикуется.

Форма хранит actual `Work`, предоставляет отмену владельцу и удерживает окно
при обычном закрытии до завершения worker. Принудительный Dispose запрашивает
отмену, не блокирует UI и завершает ожидающие UI-dispatch promises; поздние
результаты не обновляют закрытый интерфейс. В итоговой tray-интеграции требуется
общий gate с backup/maintenance и bounded shutdown wait, сохраняющий владение
незавершённым файловым вызовом.

| Проверка | Локальный статус |
| --- | --- |
| Публичные исходники, docs tests, whitespace | PASS, см. локальные команды в отчёте commit. |
| Windows release compilation | NOT_CHECKED |
| Реальные CurrentUser DPAPI, чистый импорт после удаления источника и native UI | NOT_CHECKED; добавлены `HomeVpnPortableArchiveTests.cs` и отдельный вызов в `Test-HomeVpnRelay.ps1`. |
| Независимый decoder, другой процесс с паролем через stdin | NOT_CHECKED, проверяет формат и process isolation под тем же пользователем. |
| Tamper/header/длина/password/schema/duplicate/path/junction/source lock/source mutation | NOT_CHECKED; harness вызывает production API, использует реальные файлы и NTFS junction. |
| UI heartbeat, single flight, close/dispose/deadline cancellation, staged import и actual directory commit boundary | NOT_CHECKED; native формы, блокировка I/O, сокращённый injected deadline и наблюдение реального опубликованного каталога. |
| Новый HomeVpnService и прежние pending fences, отсутствие автоактивации/изменений settings/vault/proxy journals | NOT_CHECKED; отдельная изолированная CI fixture сохраняет и возвращает существующий private root. |
| Другой Windows-пользователь/ПК, физический HDD/VHDX | NOT_CHECKED; требуется отдельная проверка владельцем. |

Счётчик закрытых критериев не меняется до Windows-проверки и review итогового
состава. Никакие службы, учётные записи Windows, установленная программа или
конфигурация VPS этим этапом не изменяются.
