# F09: владелец фоновой суточной очистки

Статус исходников: independent source/tests/contracts review **APPROVE / FROZEN**; native Windows CI ещё не подтверждён. Общий исторический счётчик остаётся 22/31 до проверки всего пакета F09.

`VaultDailyRuntime` владеет отдельной raw-задачей. Открытие и сохранение остаются в `VaultWork`; замена этой задачи не теряет незавершённую очистку. Runtime не ожидает `VaultWork`, поэтому открытие после неправильной аутентификации может ждать суточную очистку без цикла ожидания. Правильный PIN обходит этот барьер.

Провайдер корня, чтение часов, DPAPI, восстановление журнала и CAS вызываются только в worker. Наблюдение даты на STA берёт короткий замок для метаданных. После ошибки сохраняется очередь и назначается фоновый повтор с интервалом не менее 30 секунд по монотонному времени. `CheckRetry` на суточном таймере не читает файлы и часы календаря; он запускает единственную задачу только после наступления срока. Новый день, явная попытка ложного открытия или возобновление владельца могут потребовать более ранней проверки. Успешный результат снимает повтор, а здоровый текущий набор не пересканируется каждую секунду.

Runtime удерживает идентификатор поколения, его локальный день и первую наблюдённую отличающуюся дату. Возврат часов A → B → A не перезаписывает B. Метаданные наблюдений из worker сохраняются также при его ошибке или отмене; последующая попытка на A не возвращает прежнее поколение в работу. Результат worker не содержит PIN, сеанс или набор записей. Неизвестное новое поколение другого писателя проверяется по его собственной идентичности и не удаляется по старому токену.

Принятый lease хранит короткий callback публикации неизменяемого токена в runtime. Обратной ссылки runtime на lease нет. Если сохраняющий worker увидел B уже после удаления ссылок из закрытого UI и его собственная CAS-очистка не удалась, токен всё равно остаётся у владельца фоновой очистки. Это проверяется настоящим persistence lease и эксклюзивной блокировкой собственного файла Windows CI.

Для одного активного открытия приложения runtime хранит эпоху и первые две различные даты после её захвата. `BeginOpening` атомарно принимает фактический день worker перед захватом эпохи; старая дата STA до этого момента не уничтожает новый набор, созданный уже на следующем дне. Поздняя регистрация lease проверяет наблюдения после захвата и очередь уже известных инвалидаций. Новый захват эпохи не разрешает прежнее поколение, которое ещё ожидает очистку. Регистрация сохраняет метаданные и для durable binding, принятого перед поздней отменой открытия.

`Pause` не запускает новую очистку и сохраняет очередь. Уже начавшаяся raw-задача должна завершиться перед обслуживанием. После завершения исходных открытий и сохранений `SealAndDrain` замораживает новые наблюдения UI и доводит все уже принятые инвалидации до durable результата, включая очередь, полученную во время паузы. `HasPendingExpiry` отличает незавершённое обязательство очистки известного поколения от ошибки неизвестного вспомогательного файла. Наличие такого обязательства после ошибки запрещает передачу обслуживания; повреждение неизвестного sidecar не лишает пользователя выхода и правильной аутентификации. `Resume` снимает заморозку и разрешает проверку состояния заново. `Close` отменяет владельца без синхронного ожидания, сохраняет raw-задачу для подтверждения её завершения и не публикует UI.

Подготовлены native-проверки только на собственных временных каталогах Windows CI: фоновое открытие отсутствующего суточного файла; сохранение точных байтов привязки в тот же день; наблюдение ABA при закрытом окне; запрет поздней публикации открывающегося сеанса; сохранение первого наблюдения после ошибки часов; отсутствие повтора IO на каждом timer tick; автоматический повтор после настоящей эксклюзивной блокировки Windows с сокращённым интервалом только внутри fixture; отмена отдельного waiter; защита нового поколения другого писателя; финальная очистка очереди обслуживания; поздний токен настоящего сохраняющего lease после потери UI-владельца. Отдельные проверки используют настоящий application context: фоновая очистка при старте, настоящее успешное открытие правильным PIN при удерживаемой очистке, общий трёхсекундный shutdown barrier, повтор выхода после settlement, принудительное Dispose без ожидания UI, возобновление после отмены подготовки выхода, единый снимок даты B → A для активного окна, отказ после ошибки финальной очистки и разрешённый выход при неизвестном повреждённом sidecar без удаления его байтов.

Проверки не меняют системные часы и не обращаются к устройствам владельца. Наблюдение локальной даты не является защищённым внешним источником времени; изменения, которые приложение не могло наблюдать, не выдаются за проверенное событие. Архивная политика и механика переноса данных этим файлом не расширяются.
